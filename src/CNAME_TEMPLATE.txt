Hosting moved from GitHub Pages to Netlify (required for Decap CMS's git-gateway
login to work — GitHub Pages has no equivalent). The repo itself stays on GitHub;
Netlify just builds and serves from it. This file is a reminder of the domain
cutover steps, not something Eleventy or Netlify reads.

When ready to point www.vidhicorplegal.com at the Netlify site:
1. In the Netlify site dashboard: Domain management -> Add a domain ->
   www.vidhicorplegal.com (and the apex vidhicorplegal.com if you want both).
2. Add the DNS records Netlify shows you at your domain registrar — typically a
   CNAME for "www" pointing to the Netlify subdomain (e.g. your-site.netlify.app),
   plus Netlify's ALIAS/A records for the apex domain.
3. Once DNS propagates, Netlify auto-provisions the HTTPS certificate — no
   manual step needed there (unlike GitHub Pages).
4. Set the old GitHub Pages custom domain (if one was configured) back to none,
   or leave the repo's Pages source disabled, so the two hosts don't fight over
   the same domain.

Do this only when DNS is actually ready — pointing the domain before the Netlify
site exists or before Identity/Git Gateway are enabled can break the current live
URL and lock out CMS login.
